# CI entry points

Workflows call these scripts instead of running cargo or pnpm themselves, so a local run is the same as a CI run. Each script finds the repo root on its own, so it runs from any directory.

| Script | What it does | Called by |
| --- | --- | --- |
| `check-rust` | `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo build`, and `cargo test` on the workspace, with `--locked`. The tests include the protocol sample checks and the generated TypeScript staleness check. | `ci.yml`, `rust` job on macOS arm64, Linux x86_64 and arm64, and Windows x86_64 and arm64 |
| `check-app` | In `apps/desktop/`: `pnpm install --frozen-lockfile`, `pnpm check` (format, lint, type-check), `pnpm test`, and `pnpm build`. | `ci.yml`, `app` job on macOS, Linux, and Windows |
| `launch-app` | Launches the app `check-app` built, with a check preloaded into its main process (`electron -r`), and fails unless the window loads, `window.parallax` answers over IPC, and React renders, with no renderer console errors (CSP violations included), then checks the app quits with exit 0. Gives up after 60 seconds. Downloads Electron's binary on first run. On Linux with no `DISPLAY` it runs under `xvfb-run`. | `ci.yml`, `app` job on macOS, Linux, and Windows |
| `e2e-app` | Builds the app, and `plxd` with `--features fake-backend` unless `PLXD_PATH` names one, then runs `pnpm e2e` (under `xvfb-run` on Linux with no `DISPLAY`): Playwright launches the built app against that `plxd` in a temporary data folder, with `PLXD_FAKE_BACKEND` naming the script its workers play, and checks connecting, starting a thread, its output, and Stop, and signing in to a fake Codex in a terminal. | `ci.yml`, `e2e` job on macOS, Linux, and Windows, with the `plxd` the `rust` job built and uploaded for that OS |
| `package-app` | Builds the app's installer and its update metadata for this OS and arch into `apps/desktop/release/` (0029, 0030): `cargo build --release -p plxd` for the target (the static musl target on Linux), `pnpm install --frozen-lockfile`, `pnpm build`, then electron-builder, which puts `plxd`, `plxd.version`, and `app-update.yml` in the package's resources. The installer is a dmg and a zip on macOS, nsis on Windows, and an AppImage on Linux, with the channel's `latest*.yml` or `nightly*.yml` and blockmaps. `PLX_VERSION` stamps the version (default `0.0.0-local`) into the app and into `plxd.version`, which the bundled `plxd` reports; nothing is committed. `PLXD_BIN`, if set, is where a release `plxd` is kept between builds: packaged as is when the file exists, else built and copied there (`release.yml` caches it). Unsigned unless `CSC_KEYCHAIN` (a keychain holding the certificate, as `release.yml` makes) or `CSC_LINK` is set, which on macOS signs with that certificate, and notarizes too when `APPLE_API_KEY`, `APPLE_API_KEY_ID`, and `APPLE_API_ISSUER` are set (`release.yml` doesn't set them). Runs no tests or lint. | `release.yml`, `build` job on macOS arm64, Linux x86_64 and arm64, and Windows x86_64 and arm64 |
| `plan-release` | Decides the release (0051): a scheduled nightly of the default branch when it has moved and the last nightly is at least six hours old, a manual nightly immediately, a stable promotion of the latest nightly's commit (or `COMMIT_INPUT`), or a dry run of the selected branch. Prints `tag`, `version`, `channel`, `sha`, `build`, and `dry_run` for `GITHUB_OUTPUT`. | `release.yml`, `plan` job |
| `draft-release` | Prints `build=false` when the release `TAG` exists with `SHA256SUMS` (complete), `build=true` otherwise, after creating it as a draft (notes from the channel's previous published release, prerelease for nightly, target `GITHUB_SHA`) when it doesn't exist. Fails on any error reading releases other than "not found". `DRY_RUN=1` prints the create. | `release.yml`, `plan` job |
| `publish-build` | Attaches this build's files in `apps/desktop/release/` to the release `TAG` and publishes it (`--draft=false`, and `--latest` for standard). Installers and blockmaps first, the channel's `.yml` last, all `--clobber`; uploads nothing when every file is already attached. A Windows build attaches its `<channel>.yml` as `<channel>-win-<arch>.yml`. `DRY_RUN=1` prints the writes and treats the release as empty. | `release.yml`, `build` job, after `package-app` |
| `finish-release` | Joins the release's `<channel>-win-x64.yml` and `<channel>-win-arm64.yml` into `<channel>.yml` and attaches it when both exist; when `ALL_BUILT=true` and it joined them, writes `SHA256SUMS` from GitHub's digest of each attached file. `DRY_RUN=1` reads the two files from the folder given instead, prints the writes, and skips `SHA256SUMS`. | `release.yml`, `finish` job |
| `ssh-localhost` | Sets up key-based ssh to localhost with a throwaway key and its own sshd, and writes whether ssh is ready to a status file. Skips cleanly where it can't run. | `ci.yml`, `rust` job on macOS arm64 and Linux x86_64 and arm64 |
| `ssh-localhost.ps1` | The same for Windows, through Windows' own OpenSSH server (the image's `sshd` service, or Win32-OpenSSH's pinned MSI where the image has none) on port 22, whose sessions run in a job object as they do on a Windows host. | `ci.yml`, `rust` job on Windows x86_64 and arm64 |
| `check-ssh-attach` | Runs `plxd attach` through a real `ssh localhost` (#95) and checks the handshake answer, the ssh exit, and that `serve` outlives the session. Skips when ssh isn't ready, unless `PLX_E2E_REQUIRE_SSH=1`. `PLX_E2E_SSH` picks the ssh client, which `ssh-localhost.ps1` sets. | `ci.yml`, `rust` job on every OS |

## Requirements

- Rust: rustup. `rust-toolchain.toml` pins the toolchain and its components. In CI, run `rustup toolchain install` with no arguments as its own step before `check-rust`.
- Node, any recent version, for `check-ssh-attach`. GitHub's macOS and Linux runners have it. On Linux, `ssh-localhost` needs `openssh-server`, which the workflow installs when the image lacks it.
- Node 24 and pnpm through corepack (`corepack enable`) for `check-app`. In CI, `setup-node` reads `apps/desktop/.node-version` and the pnpm store is cached per OS on the lockfile's hash, so a warm run skips the downloads.
- `launch-app` runs after `check-app`. `pnpm install` doesn't fetch Electron's binary; requiring `electron` does, into `$electron_config_cache` (CI caches that directory per OS on the Electron version) or Electron's default cache. On Linux it needs `xvfb-run` when there is no display, and a working Chromium sandbox: on Ubuntu 24.04 and later, AppArmor blocks it until `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`, which the workflow runs. The check keeps the sandbox on rather than pass `--no-sandbox`.
- `e2e-app` needs rustup for `plxd` (unless `PLXD_PATH` is set) and Node 24 with pnpm for the app; Electron's binary, `xvfb-run`, and the Chromium sandbox are as for `launch-app`. The `rust` job rebuilds `plxd` with `fake-backend` after its checks and uploads it as `plxd-<os>`, which the `e2e` job downloads, so CI builds `plxd` once per OS. Release builds refuse the `fake-backend` feature, and a `plxd` built without it refuses to start while `PLXD_FAKE_BACKEND` is set.
- `package-app` needs rustup (on Linux it adds the musl target itself, and `musl-tools` must be installed: `sudo apt-get install musl-tools`) and Node 24 with pnpm, as for `check-app`. The first run downloads Electron and electron-builder's tools (dmgbuild, NSIS, the AppImage runtime). Without either it sets `CSC_IDENTITY_AUTO_DISCOVERY=false` unless you set it, so it never signs with a certificate found in your keychain. `release.yml` passes the signing secrets only to its macOS build.
- On Windows the scripts run in Git Bash, the workflow's default shell, except `ssh-localhost.ps1`, which runs in PowerShell 7. If the image lacks rustup, the workflow installs it first. `.gitattributes` keeps checkouts LF so they pass the formatter.

## Protocol samples

Every message in `crates/parallax-protocol/samples/v<N>/` must still decode, so a change that is not additive fails `check-rust`. The rules for adding samples are in the crate's docs.

## Protocol types

The app's TypeScript protocol types, `apps/desktop/src/protocol/generated/protocol.ts`, are generated from `parallax-protocol` and committed. After changing a protocol type, run `cargo run -p parallax-protocol --bin generate-typescript` and commit the result. A test in `cargo test` regenerates the file in memory, so `check-rust` fails while the committed copy is stale.
