# 0090: A Projects page, nav rows in the sidebar, and Spaces with instructions and files

- Status: accepted; amends [0087](0087-sidebar-rows-no-areas-or-folders.md)'s Projects drawer and [0069](0069-spaces.md)'s Spaces, and extends [0078](0078-coordinator-instructions-pinned.md)'s instructions to a Space's threads
- Date: 2026-10-27
- Issue: PLX-1108

## Context

Projects sat folded in a drawer at the bottom of the sidebar, so they were hard to see. Ryan wants the sidebar to read like Claude's: New thread and Search as rows, a row per page, a way to choose which rows show, and pinned projects listed by name. Projects get a page of cards. He also wants a second kind of project, like Claude's projects: a place that groups threads and gives each the instructions and files the user set. Spaces (0069) already group threads with no repository, but the app stopped making them in PLX-857, and they carried nothing to their threads.

## Decision

- **Two kinds of project.** A Project is a coordinator on a repository (0024). A Space groups threads with no repository. Both entry points name both: the sidebar's New project or Space opens the add palette, which leads with New Project and New Space, then the ways to add a repository; the Projects page's New project or Space menu offers the two kinds.
- **No "chat".** A thread with no repository runs commands and edits files on its computer, which "chat" doesn't convey. It reads No repo, with a laptop, on its card, in the repo filter, and in its group; New thread asks "What should we do on <computer>?"; and Mod+Shift+N is New thread without a repo. A Space's threads are threads.
- **A Space's instructions and files.** plxd keeps `instructions` (up to 32 KiB) and `files` (up to 50 paths) on the Space's repo entry, in two columns added by store migration 54. `repo/update` sets them, behind the `spaceContext` capability, and fails with `invalidParams` for an entry that isn't a Space. A file is one `host/upload` saved: its path must be a file inside the uploads folder once links are followed, which a worker's sandbox already reads (0071). The list is replaced whole, and plxd stores each canonical path once.
- **Adding a thread to a Space.** `thread/setSpace {threads, space?}`, behind the `spaceThreads` capability, adds threads to a Space, or with no `space` takes them out, and appends `thread.updated` for each that changed. plxd keeps the Space in a `space_id` column that store migration 55 adds to threads, apart from the thread's repo entry, so it keeps working in its own worktree or scratch repository, and its delete and Git menu are as before. A thread lists that Space as `space`. A thread started in a Space lives in its repository, and a Project's thread in its Project, so `thread/setSpace` refuses either with `invalidParams`. Deleting a Space deletes the threads started in it and takes the added ones out. The app counts both kinds as the Space's: on its page, its card, Pinned, the repo filter, a sidebar card's place, and the thread's crumbs. Thread details shows the thread's Space under Open in: Add to a Space opens a menu of this computer's Spaces, which also moves an added thread to another or, with Remove from Space, takes it out. A thread started in a Space only names it there.
- **What a thread gets.** Each CLI process of a thread in a Space, started there or added, gets the Space's name, its instructions, and its files' paths on the system-prompt channel 0078 built for the coordinator, read as they are when the process starts. The agent reads a file when it helps, as it does an attachment.
- **The new sidebar is a beta.** Settings has a Beta section, with a flask, whose New sidebar switch turns on the sidebar this record describes. Off, the default, the sidebar is the classic one 0087 left: the search box with the filter, New project or repository, and New thread in its head, Projects in their drawer and atop the list when one needs the user or matches a search, and Pull requests and Usage in its footer. The choice is kept on this computer. The Projects page, a Space's page, and Thread details' Space are the same under either.
- **The sidebar's head.** What makes something, then what finds it, then where things are: New thread, New project or Space, Search, and Projects, as rows, then More, a divider that folds open to Pull requests and Usage, which leave the footer. They grow in under Projects with the rest, the divider moving below them as Less, and fold away again. Settings › Beta switches each of the three pages between the head and More, kept on this computer. Under them, Pinned lists pinned projects of both kinds by icon and name, with the status the sidebar's thread cards show (Needs you, Working, Done), folds, and opens each; a right-click or its actions button opens its menu.
- **The Projects page.** Built from the other pages' parts: Usage's heading with New project beside it as a tool button, then Pull requests' search, Usage's segmented All, Projects, and Spaces filter when there are both, and Pull requests' Sort button (Recent, Name, Created), then Pinned and Other projects as a grid of cards, up to three across. A card is washed in its own color: its icon on a tile of that color and its status (the sidebar's Needs you, Working, Done) or its age, then its name and its latest thread's title, then a footer with a Project's branch or a Space's files and instructions, and how many threads it has. Hovering lights it from the corner and lifts it. A project with an uploaded image (0038) takes its color from the image: the average of a 16-pixel copy, weighted toward its vivid pixels. Under Pinned, an image stays grayscale until its row is hovered or open, as a glyph stays gray. Its menu holds Pin, then the Project menu 0087 put on its row (Rename, Change icon, Full access, Autonomy, Fresh session, Delete), or for a Space Rename, Change icon, and Delete.
- **A Space's page** is New thread laid out as a page, and its crumbs end at the Space. The Space's header runs across the top in place of the question: a link back to Projects, then its icon, bare in its color, and its name on one line, Pin, and its menu. Where its plxd keeps icons, hovering the icon covers it with a pencil, and clicking it opens the icon picker. Under it, the composer at full width, whose hint asks for anything rather than code, with the computer bar under it listing this computer and each other computer that has a Space of the same name (Spaces live on one computer), then two columns that start on one line. On the left, its threads as the sidebar's thread cards (the Space's icon and name, the status or age, the title in bold, its computer and the provider's logo), or an empty state saying what a thread here gets. A plus beside the heading opens a picker of this computer's threads outside the Space, newest first, with a search and a box to check on each, and Add puts the checked ones in. Each card shows the sidebar's Archive in place of its status on hover. On the right, one panel that stays in view: Instructions at reading size with Edit, and Files as cards two across, each a page in a frame (a PDF's first page, or a text file's first lines, on a white sheet that runs off the bottom; an image fills its card), as the composer's file cards now preview too, its name under it, and Remove, then an Add card, the panel taking a drop anywhere on it. Narrow, the panel goes under the threads.
- **Access in a Space.** A Space's threads pick their Access as any thread does, new or open, which PLX-744 had hidden.
- **Pins** are kept on this computer, as the sidebar's other view choices are.
- **Projects leave the sidebar's list.** The drawer is gone, and a Project shows in the sidebar only under Pinned, even when it needs the user or matches a search, unlike 0087. Pinned's dot, a card's status on the Projects page, and ⌥↓ still lead to one that needs the user.

## Rejected

| Option | Why not |
| --- | --- |
| Moving an added thread's repo entry to the Space | Its worktree or scratch repository, its cleanup on delete, and its Git menu all follow the repo entry, and a thread in a repository would lose it. |
| A new kind of project in plxd | A Space already is a named group of threads with its own entry, and 0069 rejected a parallel table. |
| Writing the instructions as `CLAUDE.md` and `AGENTS.md` in the Space's repository | Each backend reads a different file, a thread's worktree is cut before a later change, and the files would show in its diff. |
| Copying files into the shared context folder | A thread's sandbox can't read it (0044), and it holds Markdown only. |
| Keeping the Projects drawer, or Projects that need the user atop the list | The page and Pinned show every project, and Projects in the thread list crowd it. |
| Pins in plxd | Thread pins moved there for mobile; project pins are a view choice until another client needs them. |

## Consequences

- A Space thread's open CLI process keeps the instructions it started with. The next process, as after a restart or a backend switch, reads the new ones.
- Claude Code may ask before reading a file outside the thread's worktree, as with an attachment, in a mode that asks.
- An older plxd has no `spaceContext`, so the page shows only its threads there, and no `spaces`, so New project offers only a Project.
