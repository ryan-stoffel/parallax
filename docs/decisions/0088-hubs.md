# 0088: Account pools are gone, several accounts warn, and a CLIProxyAPI hub is how to use many

- Status: accepted; supersedes PLX-1033's account pools
- Date: 2026-10-26
- Issue: PLX-1068

## Context

PLX-1033 added account pools: a provider instance with `members`, other instances of its kind, that started each thread on the member with the most usage left. That makes Parallax switch the user's subscriptions on its own. Vendors can flag or ban accounts that rotate like that, and a pool needs every account signed in on every computer that runs it, each from its own IP.

[CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) is a self-hosted proxy that holds many Claude Code and Codex sign-ins, balances requests across them, and serves them as OpenAI-, Claude-, and Codex-compatible APIs, with a management API for its accounts ([docs](https://help.router-for.me/), [Theo's setup guide](https://gist.github.com/t3dotgg/59a521d2ee8d70aaf90e280c175072af)). T3 Code makes the same call: no account switcher in the app, because it risks bans, and a self-hosted CLIProxyAPI for a bigger pool.

## Decision

- **Pools are removed.** `ProviderInstance` has no `members`, and plxd has no pool checks or member placement. A `providers.json` that still holds a pool loads without it, and plxd logs that it dropped it. Its members were instances of their own and stay. A thread that ran on a member keeps its account, so it keeps running there.
- **Several accounts stay allowed, with a warning.** A host may keep more than one instance of a kind, each with its own home (`CODEX_HOME`, `CLAUDE_CONFIG_DIR`). plxd expands `~/` in a home, makes the folder, and probes each account in its own home, behind the `accountHomes` capability, which replaces `accountPools`. The Add provider dialog warns when the host already has an account of the chosen subscription agent, and in Settings > Providers each instance of such a kind after the first has a warning mark whose popover says several accounts in one app aren't supported, that switching between them puts the accounts at risk, and that a CLIProxyAPI hub is the recommended setup, with links to its docs and Theo's guide.
- **A CLIProxyAPI hub is the supported way to use many accounts.** Parallax adds hubs per host as Settings > Providers > Hubs (PLX-1069): one entry that routes Claude Code (`ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN`) and Codex (`-c` `model_provider` overrides with an `env_key`) through the hub, and reads its accounts and limits over its management API. Accounts sign in to the hub from Parallax over that API (PLX-1070).

Rotating subscriptions inside the app risks the accounts. One hub keeps every account's sign-in fresh from one residential IP, and every computer that runs Parallax uses it, so no computer juggles logins.

## Consequences

- An older app that still offers pools sees no `accountPools` on a new plxd and hides them. A pool an older plxd saved is gone after an upgrade, without asking.
- The model picker keeps one rail button per kind with an account chooser, for separate accounts.
- Until Hubs exist, the warning's popover links to CLIProxyAPI's docs only. Once they do, it also opens Settings > Providers > Hubs.
- [0046](0046-project-scheduler.md) still places a Project's children on another instance of the same kind with more headroom. That is the same switching between accounts this record warns about, and is left to PLX-1071.
