# 0062: Each turn is checkpointed, diffed, and revertible

- Status: accepted; supersedes [0052](0052-orchestration-kernel.md)'s per-turn checkpoints (PLX-485, never built) and in part [0014](0014-agent-runs.md) (plxd commits a plain thread's work when its CLI exits)
- Date: 2026-10-09
- Issue: PLX-636, for PLX-647

## Context

plxd commits a run's worktree when its CLI exits (`Actor::finish` and `commit_all` in `daemon/src/agents/actor.rs`, `daemon/src/worktree/mod.rs`), and `agent/diff` diffs that commit against the worktree's base (`daemon/src/agents/review.rs`). Three things depend on that commit. Land's send-back starts a merge in a Project child's worktree and lets that commit conclude it (`start_merge` in `daemon/src/worktree/landing.rs`), because a child is told never to run git. `agent/accept` merges the run's commit. The sidebar's +N −M (`AgentsBar.tsx`, `ProjectHome.tsx`) comes from `record_diff` on it (`actor.rs`). Nothing records the worktree per turn, and no turn can be undone. The app's Changes panel is an empty state ("No changes yet", `apps/desktop/src/renderer/SidePanel.tsx`), and the renderer never calls `agent/diff` or `agent/accept`. 0052 specified per-turn refs, but PLX-485 was never built.

T3 Code (`apps/server/src/`):

- **Refs.** `refs/t3/orchestration-v2/checkpoints/<scope hash>/ordinal/<n>` (`orchestration-v2/CheckpointService.ts`), one root scope per thread.
- **Capture** (`vcs/GitVcsDriver.ts`): a temporary `GIT_INDEX_FILE` seeded from the real index, `add -A` (untracked files that aren't ignored are included), `write-tree`, `commit-tree` with no parent, `update-ref`. It sets `core.fsmonitor=false` and handles sparse checkouts. A per-folder lock serializes capture, restore, and delete. A folder that isn't a git repository gives `missing`.
- **When.** The baseline (ordinal `n - 1`) is captured when a run starts, if it's missing. A `checkpoint.capture` effect runs after a root run ends `completed`, `interrupted`, or `cancelled`, not `failed` (`orchestration-v2/RunExecutionService.ts`, `CheckpointCaptureService.ts`). Capture is idempotent. Subagent nodes inside a run get no app-level checkpoint, but a delegated child thread is a normal thread, and its root runs are checkpointed in the folder it shares with its parent. Each records per-file line counts and a `checkpoint` turn item.
- **Diffs** (`checkpointing/CheckpointDiffQuery.ts`): `getTurnDiff(from, to)` over `ready` checkpoints of completed runs, whitespace ignored by default, capped at 10 MB. `getFullThreadDiff` is `getTurnDiff(0, to)`. The web DiffPanel offers Changes (branch against base), Uncommitted, Latest turn, and Turn N (`apps/web/src/components/DiffPanel.tsx`).
- **Revert** (`orchestration-v2/Orchestrator.ts`, `CommandPolicy.ts`, `CheckpointRollbackService.ts`, `CheckpointRestoreSafety.ts`): `checkpoint.rollback` needs a provider that can roll back its conversation (`canRollbackThread`, `providerCanRollbackConversation`, `providerRollbackReturnsSnapshot`: Codex, Claude, OpenCode, ACP, and Pi yes; Cursor no) and a `ready` checkpoint. The server has no idle check: the web UI and the Claude adapter refuse while a turn runs. The `provider-thread.rollback` effect rolls back the provider first (Codex `thread/revert`, `provider/CodexThreadRevert.ts`, only for threads with paginated history; Claude by closing the live query and resuming at the message, [0061](0061-claude-agent-sdk.md)), then restores files with `git restore --source <checkpoint> --worktree --staged`, `clean -fd`, and `reset`, then deletes refs above the target and marks later runs `rolled_back` and their checkpoints `stale`. Restoring files needs an isolated worktree: no other thread, session, or project root may share or contain the folder. The dialog "Edit from here?" offers "Revert files too" and "Revert and keep changes", and puts the prompt back in the composer (`apps/web/src/components/ChatView.tsx`).
- T3 never deletes checkpoint refs except on rollback, not even when a thread is deleted.

## Decision

plxd does the same, on [0059](0059-orchestration-rewrite.md)'s runs and effects.

- **Refs** are `refs/parallax/checkpoints/<thread id>/<ordinal>`, in the thread's folder: its worktree, or the checkout of a Current checkout thread. Thread ids are UUIDs, so they need no hashing. A `checkpoints` row records the ref, the run, line counts per file, and the status (`ready`, `missing`, `error`, `stale`).
- **Capture** is T3's, with #166's pinned git folder, no hooks, and `core.fsmonitor=false`: temporary index from the real one, `add -A`, `write-tree`, `commit-tree` with no parent, `update-ref`. It never touches the user's index or branch. The baseline is captured when a run starts and the previous ordinal has no checkpoint. `checkpoint.capture` is enqueued in the transaction that ends a root run `completed`, `interrupted`, or `cancelled`. It is replay-safe and idempotent, so a restart runs it again. The thread's next run waits for it, since effects on one thread run in order. A coordinator writes nothing (0024) and gets none.
- **What commits the work.**
  - **A Project child** is still committed by plxd when each of its runs ends, as today, so Land, its send-back's merge, and the child's no-git rule (0045) keep working. The commit is part of the run's terminal effects, before `checkpoint.capture`.
  - **A plain thread** isn't committed at the end of a turn, as in T3. Its work stays in the worktree, and its checkpoints record each turn. `thread.accept`, `git.commit`, `git.push`, and `pr.open` (0059) commit the worktree first when it has changes, so Accept, Commit, Push, and Open PR work on demand as before.
  - **Diff stats.** The sidebar's +N −M come from the thread's diff against its base, worktree included: for a plain thread from its newest checkpoint, for a Project child from its commit. `agent/diff` keeps working for the committed range.
- **Diffs.** `orchestration/getTurnDiff {threadId, from, to}` and `orchestration/getFullThreadDiff {threadId, to}`, T3's rules: `ready` checkpoints of completed runs, whitespace ignored unless asked, 10 MB cap.
- **The Changes panel** shows T3's scopes: Changes (the branch against its base), Uncommitted, Latest turn, and Turn N. Each turn's checkpoint item in the transcript opens its diff.
- **Revert** is `checkpoint.rollback {threadId, checkpointId, restoreFiles}`, refused with a reason before anything changes unless the checkpoint is `ready` and the adapter declares `can_rollback_thread` ([0060](0060-provider-sessions.md)): Codex `thread/revert` (for threads with paginated history), Claude by `resumeSessionAt`, OpenCode and ACP where their protocol supports it, Cursor refused. plxd also refuses while a turn runs. T3 leaves that check to its UI and Claude adapter, and plxd makes it in `decide` so every client gets it. With `restoreFiles`, the thread's folder must be an isolated worktree, by T3's rule. So a Current checkout thread, and a delegated child that shares its parent's worktree, can revert only the conversation. The effect runs T3's order: provider, files, stale refs, then the projection changes in one transaction.
- **The dialog** is T3's: "Edit from here?" with "Revert files too" and "Revert and keep changes", and the reverted prompt back in the composer.
- **Retention.** No count cap, as T3. Unlike T3, plxd deletes a thread's refs when the thread is deleted or accepted, as it deletes its worktree and branch, so a deleted thread doesn't keep its objects alive.

## Consequences

- Every turn's changes are reviewable in the app, and a turn can be undone, with or without its files.
- Every finished turn costs one `git add -A` into a temporary index before the next turn starts. A huge untracked tree makes that slow. PLX-647 measures it on a large repository.
- A plain thread's work is no longer committed at the end of each turn. It stays uncommitted until the user commits, pushes, opens a PR, or accepts, or the agent commits. Checkpoints keep it recoverable in the meantime. Project children are committed as before.
- Cursor threads can't revert. Threads in the user's own checkout can revert the conversation but not the files.
- Checkpoint refs keep objects reachable until their thread is deleted or accepted.
- PLX-647's issue text says Codex `thread/rollback`. The method is `thread/revert`.

## As built (PLX-647)

Where it differs from the above:

- **A plain thread still commits at the end of each turn.** Commit, Push, Open PR, Accept, and the sidebar's +N −M keep working unchanged, and the actor's turn end stays as it was. A checkpoint is captured into its own temporary index, so it doesn't depend on the commit. A revert with its files leaves the restored files as uncommitted changes, which the next turn's commit records. Dropping the per-turn commit is a follow-up.
- **No `checkpoints` table.** A run's checkpoint (status, and per-file line counts) is on its `thread_runs` payload. The `thread.checkpoint` event writes it, and the `thread.reverted` event marks the runs a revert undid `rolledBack` and their checkpoints `stale`. The ref is named by the thread and the run's ordinal. The app lists a thread's turns with `orchestration/threadRuns`.
- **Capture.** The graph fold enqueues `checkpoint.capture` in the transaction that ends a run. It does this for live events only, not for the importer or a fork's copied transcript. A capture that fails records `error` rather than retrying. Turns aren't effects (0060's as-built), so before the actor hands its CLI a new turn, it waits for the thread's open captures, for at most 30 s. It then captures the ordinal the turn starts from if that ref is missing: after a revert, or for a thread from before this change. A worktree's ordinal 0 is its base commit, which needs no scan. A Current checkout thread's is captured from its checkout. Sparse checkouts and the index's skip-worktree and assume-unchanged flags get none of T3's special handling.
- **Diffs** accept the checkpoints of runs that were `interrupted` or `cancelled`, as well as `completed` ones, so a stopped turn's changes can be reviewed. T3 serves only completed runs'.
- **Revert** is `checkpoint.rollback {threadId, ordinal, restoreFiles}` through `orchestration/dispatch`, carried out by the thread's actor between its turns. Before anything changes, it refuses with `revertRefused` when a turn or a push runs, when the checkpoint isn't `ready` or its ref is gone, when the backend lacks `Capabilities::rewind`, or, with `restoreFiles`, when the thread has no worktree of its own. The actor then ends the idle session and calls `Backend::rewind {session_id, cwd, turns}`, which returns the session to resume. The files, the refs above the target, and `thread.reverted` follow.
- **Provider turns** are counted from the graph, since plxd records no native turn ids. A run steered into the turn before it counts with that turn.
- **Codex** rewinds on the login's shared app-server, as T3's adapter does: `thread/read` (paginated history only), `thread/resume` if the thread isn't loaded, `thread/turns/list` newest first, then `thread/revert {beforeTurnId}`, then `thread/unsubscribe`. **Claude** reports `rewind: false` until PLX-646's Agent SDK adapter implements `rewind` (`resumeSessionAt`), so it is refused like Cursor, ACP, and OpenCode.
- **The app** reverts from the Changes view: a turn's Edit from here opens T3's dialog and returns that turn's message to the composer. The transcript drops the turns a revert undid.
- **Measured** on an Apple-silicon Mac (release build). A capture takes a median of 216 ms on a 27,690-file repository and 239 ms on a 100,000-file one, against 244 ms and 324 ms for the per-turn commit. It runs after the turn has ended. The first capture after a fresh checkout takes about 1 s, because git rehashes the files the checkout just wrote. The ref check before each turn takes about 10 ms. A 102-turn thread's whole diff takes 17–25 ms, one turn's about 11 ms.
